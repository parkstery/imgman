# imgman 앱 점검 보고서

점검일: 2026-10-29 (Asia/Seoul)

## 종합 판단

현재 코드는 타입 검사와 프로덕션 빌드를 통과하고, SVG·방사상 배열·자동 크롭의 기존 검증도 통과한다. 이미지와 벡터를 함께 편집하는 기능 구성, 속성 패널, 레이어, 프로젝트 저장 및 여러 내보내기 형식은 이미 갖춰져 있다.

그러나 **편집 결과의 신뢰성을 해치는 오류가 실제로 재현된다. 기능 추가보다 히스토리, 파일 검증, 잠금, 모달 입력 차단을 먼저 보강하는 것이 좋다.** 전체 재작성보다 문서 상태와 편집 명령을 중심으로 단계적으로 리팩터링하는 편이 적합하다.

## 점검 범위와 제한

- 작업 폴더의 현재 소스를 기준으로 검토했다. 기존 미커밋 변경인 `CanvasArea.tsx`, `Toolbar.tsx`도 포함했으며 해당 소스는 수정하지 않았다.
- React/TypeScript/Vite 설정, 주요 편집 상태, 레이어·그룹, 파일 입출력, SVG/래스터 내보내기, UI 이벤트를 검토했다.
- 별도 브라우저 작업 공간에서 로컬 개발 서버와 프로덕션 preview를 사용했다. 오류 재현에는 합성 프로젝트를 사용했으며 실제 사용자 프로젝트는 변경하지 않았다.
- 화면 캡처 도구는 두 차례 타임아웃이 발생했다. UI 평가는 DOM·접근성 트리·실제 클릭과 키보드 동작·레이아웃 좌표 및 소스에 근거한다. 색상 대비와 시각적 완성도에 대한 픽셀 단위 평가는 포함하지 않는다.
- 실제 OS 클립보드 권한, 대용량 이미지 스트레스, 여러 브라우저·실기기 터치, 배포 서버 설정, 의존성 보안 공지는 이번 점검에서 검증하지 않았다.

## 발견한 오류와 수정 방향

P1은 편집 내용 손실·앱 종료·보호 기능 우회로 우선 수정할 항목, P2는 동작 일관성과 사용성을 위해 후속 수정할 항목이다.

### 1. P1 — 실행 취소 후 첫 편집이 기록되지 않고 Redo가 새 편집을 덮어씀

근거: [App.tsx:466](C:/20.HDev/imgman/src/App.tsx:466), [App.tsx:535](C:/20.HDev/imgman/src/App.tsx:535)

프로덕션 재현:

1. 그리드를 켠다.
2. 실행 취소한다. 그리드가 꺼지고 Redo가 활성화된다.
3. 눈금자를 끈다. 새 편집인데 Undo가 비활성화된 채 Redo가 남는다.
4. Redo를 누르면 그리드와 눈금자가 모두 켜져 새 편집이 덮어써진다.

Undo/Redo가 `isHistoryActionRef.current = true`로 설정하지만 복원 자체는 `pushHistory`를 호출하지 않는다. 남은 플래그가 다음 사용자 편집의 히스토리 저장을 건너뛴다.

수정: 문서와 히스토리 인덱스를 하나의 reducer에서 원자적으로 갱신한다. Undo 이후 새 명령은 미래 히스토리를 제거하고 반드시 새 스냅샷을 만든다. 복원 동작을 구분하는 플래그에 의존하지 않도록 한다.

별도로 개발 모드에서는 그리드 토글을 되돌리는 데 Undo가 두 번 필요한 현상도 관찰됐다. `handleUpdateConfig` 등 상태 updater 내부에서 다른 상태를 변경하는 부작용이 있으며 StrictMode 환경에서 중복 히스토리가 생길 수 있다. updater를 순수 함수로 만드는 수정이 함께 필요하다.

### 2. P1 — 형식이 잘못된 프로젝트 JSON으로 앱이 빈 화면이 됨

근거: [App.tsx:1976](C:/20.HDev/imgman/src/App.tsx:1976), [main.tsx:7](C:/20.HDev/imgman/src/main.tsx:7)

`config`, `layers`, `elements`의 존재 여부만 검사하고 상태로 넣는다. `layers`를 배열 대신 객체로 넣은 JSON을 열자 앱 본문이 사라지고 저장 버튼도 사라졌다. JSON 파싱의 try/catch는 이후 React 렌더링 오류를 복구하지 못한다.

수정: 상태 반영 전에 전체 스키마를 검사한다. 배열 여부, 최소 한 개의 레이어, ID 유일성, 요소 타입, 필수 필드, 유한한 좌표·크기·투명도, `layerId` 참조, 버전을 검증한다. 검증 실패 시 기존 문서를 유지하고 이유를 표시한다. 루트 ErrorBoundary도 추가해 예상 밖 오류에서 복구 경로를 제공한다.

### 3. P1 — 잠긴 객체와 잠긴 레이어의 객체를 삭제할 수 있음

근거: [App.tsx:864](C:/20.HDev/imgman/src/App.tsx:864), [App.tsx:874](C:/20.HDev/imgman/src/App.tsx:874), [CanvasArea.tsx:1060](C:/20.HDev/imgman/src/components/CanvasArea.tsx:1060)

실제 재현:

- `locked: true` 객체를 레이어 목록에서 선택하면 속성 패널 삭제 버튼이 활성화되며 삭제된다.
- 레이어를 UI에서 잠근 다음 목록의 객체를 선택하고 Delete를 누르면 삭제된다.

일부 이동 경로에는 잠금 검사가 있으나 삭제·속성 변경·도구 경로에 공통으로 적용되지 않는다. 캔버스 이동도 클릭한 객체의 소속 레이어보다 `activeLayer.locked`에 의존하는 부분이 있다.

수정: 모든 변경 명령에서 `canEdit(element, document)`와 같은 공통 검사를 사용한다. UI 버튼 비활성화만으로 막지 말고 실제 명령 실행 시에도 확인한다. 잠금은 선택 허용 여부와 수정 허용 여부를 구분해 정의한다.

### 4. P1 — 모달이 열려 있어도 뒤쪽 문서에 Delete가 적용됨

근거: [App.tsx:2148](C:/20.HDev/imgman/src/App.tsx:2148), [ExportModal.tsx:191](C:/20.HDev/imgman/src/components/ExportModal.tsx:191)

객체 선택 → 내보내기 창 열기 → Delete를 누르자 내보내기 창은 그대로인데 뒤쪽 객체가 삭제됐다. 전역 단축키는 입력 요소 여부만 검사하며 모달 상태를 검사하지 않는다. 모달을 열어도 포커스가 내보내기 버튼에 남았다.

Esc로 내보내기 창이 닫히지 않으며 `role="dialog"`도 없다.

수정: 공통 Dialog를 도입하고 포커스 진입·트랩·복원, `aria-modal`, 제목 연결, Esc 닫기를 제공한다. 모달이 열렸을 때 문서 단축키를 중지하고 모달의 키 처리만 허용한다.

### 5. P2 — 복제본이 원본과 같은 그룹 ID를 유지함

근거: [App.tsx:928](C:/20.HDev/imgman/src/App.tsx:928), [App.tsx:1508](C:/20.HDev/imgman/src/App.tsx:1508), [radialArray.ts:111](C:/20.HDev/imgman/src/utils/radialArray.ts:111)

그룹 `g1`의 객체를 선택하고 Ctrl+D로 복제한 뒤 JSON으로 저장해 확인했다. 복제본의 객체 ID는 바뀌었지만 `groupId`는 원본과 동일한 `g1`이었다. 이후 캔버스에서 같은 그룹의 객체를 선택하면 원본과 복제본이 함께 선택될 수 있다.

단일 복제, 여러 객체 복제, 내부 붙여넣기, 레이어 복제, 방사상 배열에 걸쳐 복제 규칙을 정리할 필요가 있다.

수정: `cloneElements` 같은 공통 함수에서 객체 ID와 그룹 ID를 함께 재매핑한다. 하나의 복제 묶음 안에서는 그룹 관계를 유지하되 원본 및 다른 복제 묶음과 분리한다.

### 6. P2 — ‘화면에 맞추기’가 실제 화면 크기를 계산하지 않음

근거: [App.tsx:2439](C:/20.HDev/imgman/src/App.tsx:2439)

버튼 동작은 `setZoom(0.85)`로 고정되어 있다. FHD 캔버스에서 실행해도 85%가 되며 캔버스가 작업 영역 밖으로 크게 남았다. 캔버스 크기·패널 너비·창 크기를 반영하지 않는다.

수정: 실제 작업 영역의 폭과 높이로 `min(availableWidth / canvasWidth, availableHeight / canvasHeight)`를 계산하고 여백을 적용한다. 패닝도 초기화해 캔버스를 중앙에 둔다. ResizeObserver로 창과 패널 변화에 대응한다.

## 기능 개선 제안

1. **작업 보존:** IndexedDB 자동 저장과 복구, 저장 여부 표시, 저장되지 않은 문서의 새로 만들기·열기·페이지 이탈 안내. 실제로 현재 앱은 새로고침하면 편집 상태가 사라졌으며 자동 복구가 없다. 새 캔버스 생성은 히스토리도 초기화한다.
2. **일관된 다중 선택:** 목록에서 Shift/Ctrl 선택, 선택 개수 표시, 여러 객체의 공통 속성 편집을 지원한다. 현재 레이어 패널은 마지막 선택 ID 하나만 받아 다중 선택 상태를 충분히 보여주지 못한다.
3. **정렬·배치 강화:** 선택 객체 기준과 캔버스 기준의 정렬을 구분하고 균등 간격 배치·스마트 가이드를 추가한다. 먼저 기존 그룹 선택과 복제의 정확성을 확보한다.
4. **내보내기 피드백:** 미리보기 실패 시 오류와 재시도를 제공한다. 현재 미리보기 예외는 콘솔에만 남는다. 대형 출력의 픽셀 수·메모리 예산을 제한하고 진행·취소를 제공한다. 현재 실제 출력 배율로 미리보기를 만들고 다운로드 시 다시 생성하므로 고해상도에서 중복 비용이 생긴다.
5. **프로젝트 형식 관리:** 스키마 버전별 마이그레이션, 원본 파일명/문서명, 최근 작업과 마지막 저장 시각을 제공한다.

## 인터페이스 개선 제안

- **작업 영역 확보:** 좌측 256px, 우측 288px 고정 패널이 공간을 차지한다. 좁은 창에서는 자동 접기 또는 오버레이 패널을 사용하고 패널 너비 조절을 제공한다. DOM 측정에서 헤더 콘텐츠가 컨테이너보다 넓어 가로 스크롤이 필요했다.
- **도구 탐색성:** 현재 미커밋 변경은 사각형·원·폴리라인·아크의 빠른 버튼을 메뉴로 합친다. 공간 절약 효과가 있으나 자주 쓰는 도구의 접근 비용이 늘어난다. 최근 사용 도형 또는 즐겨찾기를 한두 개 노출하는 방식이 적절하다.
- **아이콘 설명:** 주요 아이콘에 일관된 `aria-label`, 키보드 툴팁, 선택 상태 `aria-pressed`를 제공한다. 접근성 트리에서 이름 없는 버튼이 다수 확인됐다. `title`에만 의존하는 설명은 보완한다.
- **읽기 편한 속성 패널:** 10~11px 보조 텍스트 비중을 줄이고 기본 본문을 키운다. 상세 옵션을 접어 핵심 설정을 먼저 노출한다. 다크 테마의 대비는 별도 화면 캡처 기반으로 확인할 필요가 있다.
- **현재 작업 안내:** 선택 개수, 선택 객체의 잠금 여부, 도구별 완료·취소 방법, 저장 상태를 작업 영역에 표시한다. 그룹·방사상·크롭처럼 단계가 있는 도구는 현재 단계와 다음 행동을 유지해서 보여준다.
- **터치 입력:** 캔버스는 주로 mouse 이벤트를 사용한다. 태블릿을 지원할 계획이라면 Pointer Events와 pointer capture로 전환하고 펜·터치 입력을 실기기에서 확인한다.

2. 그룹 복제 규칙과 실제 화면 맞춤을 수정한다. 자동 저장·복구와 저장 상태 표시를 추가한다.
